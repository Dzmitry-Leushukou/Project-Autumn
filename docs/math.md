# Математическая модель Metro Lab

Действующий код вынесен в [models/](../models/README.md): отдельные файлы моделей, русские пояснения, формулы и соответствие UI. Этот документ дополняет их техническими деталями.

## Область модели и единицы

Один тип поезда и фиксированный общий парк. Ветка — простой путь или кольцо, разветвление — несколько путей с общими id станций. Общий физический перегон один. Две независимые направленные трубы на перегон; платформа на направление физического коридора. У пересекающихся только в узле линий разные платформы, у общего участка — общие. Общая станция допускает мгновенную смену ветки, разные id соединяются двусторонним пешим переходом.

Время — секунды от полуночи первого дня (по умолчанию 18000–90000, то есть с 05:00 до 01:00 следующего дня), спрос описан в минутах, длины — метры, скорость — м/с, ускорение — м/с². Координаты карты — условные единицы 0–1000, 5 метров за единицу при рисовании перегона. Геометрия не определяет длительность хода после явного ввода длины/времени.

## Ход и число поездов

Рабочая скорость v = min(v_поезда, v_ограничение_перегона). Если run_time_s задано, оно имеет приоритет. Иначе при длине L и ускорениях a,b:

- Если L ≥ v²/(2a)+v²/(2b), трапецеидальный профиль: t = L/v+v/(2a)+v/(2b).
- Иначе v_p = sqrt(2L/(1/a+1/b)), треугольный профиль: t = v_p/a+v_p/b.

Стоянка: d = d_base+(n_off+n_on)/boarding_rate_pps+d_doors+delay. d_doors = door_open_s+door_close_s только при platform_doors=true. Defaults дверей 4+6 с — допущение, не измерение. На конечной поезд выдерживает base/двери/высадку перед уходом в пул. Пассажиры, пришедшие после начала стоянки, в этот поезд не садятся.

Для пути T_оборот = 2·(Σ t_перегонов+Σ d_base_всех_станций+Σ d_doors+turnaround_s). N_формула = ceil(T_оборот/h). Для кольца T_круг = Σ t_перегонов+Σ d_base+Σ d_doors, N_формула = 2·ceil(T_круг/h). Пассажирообмен, случайность и блокировки в этой оценке отсутствуют. Поэтому это приближение, а не гарантия.

При отсутствии распределения парка вычисляются максимальные N по периодам; выдаётся min(fleet,ΣN) поездов пропорционально потребности. Если парк не меньше числа веток, сначала резервируется по одному, остаток — методом наибольших остатков от остаточных потребностей. Сумма не превышает fleet. Источник вычисленного распределения — assumption. Ноль поездов означает полное исключение ветки из маршрутизации.

## События, безопасность и диспетчер

Очередь heapq упорядочена по (время, приоритет типа, id поезда, стабильный порядковый номер). Приоритеты: генерация, пеший переход, отправление/завершение стоянки, въезд, выпуск, период, минутный срез, watchdog. Нулевой переход обрабатывается атомарно при высадке. Нет фиксированного шага движения: заблокированный поезд пробуждается освобождением конкретного ресурса. group_step_s относится к генерации спроса, а 60 секунд — только к записи срезов.

Поезд отправляется только в свободную трубу. Труба удерживается до фактического въезда на следующую платформу. При занятой платформе поезд стоит в конце трубы; при занятой трубе — на платформе. Вместимость каждого ресурса ровно один поезд, инвариант проверяется в тестах на каждом событии. Минимального безопасного интервала как настройки нет: затор появляется из занятости ресурсов.

В начале суток все поезда в пулах. Для пути ceil(n/2) у первой конечной, floor(n/2) у последней; для кольца те же доли по направлениям у depot_station. Из пула берётся минимальный (время готовности, id). Первый плановый выпуск в day_start_s. Фактический выпуск = занятие начальной платформы; следующий плановый = фактический+h текущего периода. Задержка = фактический−плановый. Опоздавший выпуск не порождает пачку «догоняющих» выпусков.

На пути после конечной поезд готов к противоположному выпуску через turnaround_s после обслуживания. На кольце разворотов нет: у депо при активном числе направления > ceil(T_круг/h) поезд отзывается, иначе продолжает круг. Остаток поездки высаженных групп сохраняется, ожидание начинается заново. После day_end_s нет новых выпусков/пассажиров. Поезда доезжают до конечной/депо; расчёт заканчивается при пустых очередях и пулах всех поездов либо в day_end_s+7200. Watchdog завершает тупик после 3600 с без отправления при наличии активных поездов.

## Спрос, модельные направления и маршруты

За шаг Δ ожидаемый вход N_i = Σ entries/(len_min·60)·Δ по активным записям станции i. Последний шаг ограничен оставшимся временем суток. При demand_noise=true используется Poisson(N_i), иначе ровно N_i, включая дроби. Отрицательные значения запрещены. Пропуски дают нулевой поток и предупреждение валидатора. Одновременные интервалы спроса одной станции запрещены.

При заданной od_matrix генерация производится по trips её записей, источник результата od_source=data. Иначе:

P(j|i) = w_j d_ij^(−β) / Σ_(k≠i) w_k d_ik^(−β),

где w_j — весь вход станции j за сутки, d_ij — стоимость кратчайшего пути без ожидания, но с пересадочными штрафами, β=od_beta. Недостижимые назначения исключаются. Если ни одного положительно взвешенного достижимого назначения нет, вход остаётся необслуживаемой очередью и учитывается в W/unfinished, а не исчезает. Направления всегда помечены model, даже если исходные входы станции реальные.

Граф состояний: узел (станция,ветка). Ребро движения в обе стороны имеет стоимость t_run+d_base+d_doors станции прибытия; смена ветки на месте стоит γ, пеший переход — γ+walk_time_s. Источник соединяется со всеми ветками станции с нулевой стоимостью, цель аналогично. Кратчайшие простые пути networkx.shortest_simple_paths рассматриваются до (1+margin)·T_shortest и max_routes. margin=0 даёт один лучший путь. Маршруты с одинаковыми станциями и местами пересадок объединяются.

Поездка — непрерывный участок без смены платформы/ветки. Её обслуживают все активные ветки, которые покрывают упорядоченную последовательность станций в нужном направлении. Пассажир садится в первый подходящий поезд любой такой ветки. Ожидаемое ожидание до поездки = 0.5 / Σ_l(1/h_l), период фиксируется моментом генерации у исходной станции.

Для K равновесных классов σ²=ln(1+diversity²), θ_k=θ·exp(σz_k−σ²/2), γ_k=γ·exp(σz'_k−σ²/2), z,z' независимы N(0,1). Время восприятия T_r,k = T_ride+T_walk+число_пересадок·γ_k+Σ expected_wait.

P(r|k,i,j)=exp(−θ_k T_r,k)/Σ_m exp(−θ_k T_m,k), P(r|i,j)=среднее по K. Перед exp из логитов вычитается максимум для численной устойчивости. Вероятности кэшируются на (пара,период). Большая θ приближает выбор к минимальной воспринимаемой стоимости. При diversity=0 все классы совпадают.

**Допущение независимости альтернатив:** частично совпадающие пути считаются независимыми; path-size logit не используется. Общая задержка и реальная переполненность не влияют на заранее выбранный маршрут. Классная неоднородность влияет на вероятности, а затем агрегируется: отдельные люди и отдельные решения классов не моделируются.

Размер группы = N_i·P(j|i)·P(r|i,j). Группа хранит route, leg, время появления, дробный size. Группы меньше 1e−9 отбрасываются; погрешность сохранения контролируется относительно потока. Совпадающие группы одного места/маршрута/leg/времени объединяются. FIFO — порядок появления. Вместимость поезда ограничена; последняя группа делится. На борту группы одного остаточного маршрута объединяются, поскольку ожидание уже начислено. Длина очереди не пропорциональна числу людей. Пассажир на пересадке выходит, проходит walk_time_s (ноль для общей станции), попадает в новую очередь; штраф γ воспринимаемый и не добавляет физическое время перехода.

Конструктор формирует 15-минутные intervals по середине t+7.5: два пика m(t)=0.25+0.75exp(−(t−510)²/(2·75²))+0.9exp(−(t−1080)²/(2·90²)); утро — 0.25+0.9exp(−(t−510)²/(2·75²)); ровный — 1. entries=peak·m(t). Все эти потоки синтетические.

## Задержки и случайность

На каждой стоянке p=min(1,p₀·(n_on+n_off)/capacity). При нулевом обмене p=0, даже если p₀>0 — буквальная формула ТЗ. Длительность логнормальна: σ²=ln(1+s²/m²), μ=ln(m)−σ²/2; exp(N(μ,σ²)). При s=0 длительность m. Причина выбора: положительность, длинный правый хвост, возможность параметризовать наблюдаемым средним/SD. В проекте это модельное допущение, эмпирическая подгонка TfL не выполнялась. На 200 тыс. выборок тест проверяет моменты с допусками 1%/2%.

SeedSequence(seed) порождает фиксированные подпотоки demand, delays, classes, search. Изменение количества вызовов одного не сдвигает остальные. Для одного seed/сценария/версий зависимостей результат побитово повторяется. Версии numpy и Python важны для переносимости побитового представления; математическая повторяемость не является обещанием одинакового бинарного float на любых платформах.

Закон сохранения на каждом событии: appeared = waiting+riding+walking+transported. В walking входят группы в переходах; они не должны исчезать из баланса. FIFO/вместимость и занятость ресурсов тоже проверяются на каждом событии тестовых сетей.

## Метрики

Ожидание каждой поездки = boarding_time−platform_arrival. При пересадке начинается новый отсчёт, суммируется по пассажиру. Очереди к моменту остановки получают ожидание до конца расчёта.

- W = (Σ ожиданий севших + ожидание оставшихся очередей)/appeared, секунды.
- D = Σ отказы каждому подходящему поезду / appeared; повторные отказы считаются повторно, D может быть >1.
- LF = Σ load при отправлении по проходам / (capacity·число проходов), E=1−LF. При нуле проходов LF=0.
- Qn=max_станций(peak_queue)/capacity.
- U=число уникальных выпущенных поездов/fleet; при fleet=0 U=0.
- Перевезено = завершившие весь маршрут; не доехало=appeared−transported.
- Фактический интервал — среднее разностей выпусков по ветке/направлению/периоду; при одном выпуске null, а не выдуманное значение. Задержка — средняя фактическая минус плановая.
- Использование по периодам — уникальные поезда с пересечением интервала нахождения вне пула и периода, включая границы без выпуска в этом периоде.
- Тепло станции=peak_queue/capacity; трубы=средняя загрузка прохода/capacity. Блокировки=время ожидания ресурса внутри моделируемых суток/длительность суток; ожидание за day_end_s не добавляется.

В train-count локальный D_l,p использует повторные отказы / севших по поездкам этой ветки за период. Это оговорённая конкретизация неоднозначного «по пассажирам, ехавшим по ветке»; при отказах и нулевой посадке знаменатель ограничен 1e−12. Остальные метрики используют точные определения выше.

Траектория хранит trips (departure, ready, actual arrival, load), stops (arrival, departure, off/on/load/delay), series каждые 60 с и queue_events. Между departure и ready поезд линейно интерполируется по карте, затем стоит в конце трубы до actual arrival. Это визуальная интерполяция, время хода рассчитано по кинематике; ускорение на карте не воспроизводится. Дельты очередей позволяют точное восстановление произвольного момента. Клиент один раз получает JSON, кадры строит локально.

## Оптимизация и подбор парка

f_A = w_wait·W+w_denied·D+w_queue·Qn; defaults 1,120,30. f_B=w_empty·E+w_fleet·U; defaults 0.7,0.3. Оба минимизируются. Варианты с тупиком/отсутствием выпусков получают (1e9,1e9) и не входят во фронт.

Переменные: целые h_l,p, кратные шагу в [min,max], и целые n_l≥0, Σn_l≤fleet; locked сохраняет исходное распределение. Repair округляет к решётке/обрезает интервалы и убирает излишек парка. Поезд привязан к ветке весь день. Снижение парка в непиковый период происходит естественно через пулы, не сменой ветки.

Собственный NSGA-II: недоминирующие ранги O(MN²), crowding distance по двум нормированным осям, бинарный турнир (ранг,−crowding,индекс). Начальная популяция: исходная, формульная, граничные интервалы и случайные возмущения. Uniform crossover по веткам одновременно переносит расписание и назначение; мутация меняет 1–4 шага интервала, опционально переносит один поезд. Родители+дети выбираются элитистским ранжированием. Дубликаты оценок кэшируются.

Каждая поисковая оценка — среднее seeds_search отдельных полных прогонов. Для каждого кандидата сразу завершаются также seeds_final; ранжирование поиска использует только seeds_search, окончательный фронт — seeds_final. Повторные seed-прогоны кэшируются, показывается population SD по seed (ddof=0), а не доверительный интервал. Используются одни seed+i для честного сравнения вариантов. Независимые оценки параллельны в multiprocessing.Pool с spawn; результаты собираются в стабильном порядке. Все числовые поля и вложенные тепловые карты усредняются; редкие строки интервалов объединяются по идентификаторам, а не позиции в списке. Отсутствие наблюдения интервала сохраняет null, а не даёт фиктивный нулевой интервал.

«Минимум ожидания» минимизирует f_A; «Минимум пустых поездов» минимизирует f_B; баланс — минимальная норма z=(f−min)/(max−min) по двум осям фронта, при нулевом span z=0, tie-break f_A. «Мой вариант» — точный исходный сценарий, может лежать вне фронта/границ поиска. Исходный сценарий, допустимый по решётке и ограничениям, включается в итоговую проверку недоминирования. Разные названия могут соответствовать одному решению при вырожденном фронте — четыре разные оптимальные точки не гарантированы.

Остановка нормального поиска определяется generations и фиксированным evaluation_budget (default 20 оценок расписаний), поэтому число выполненных оценок не зависит от скорости машины. Population — верхняя граница: при недостаточном лимите начальная популяция ограничивается половиной лимита (минимум 4), остальное остаётся для потомков. Точный исходный сценарий проверяется отдельно, уникальные seed-прогоны кэшируются. Эти ограничения не сокращают сутки, пассажиров или набор итоговых seed.

time_budget_s — аварийный wall-clock предел: ожидание процесса проверяет его каждые 50 мс, последовательный симулятор — каждые 128 событий. Незавершённые процессы прекращаются, отдельной неограниченной финальной фазы нет. Возвращается фронт только полностью оценённых по seeds_final кандидатов; при нехватке времени даже для исходного сценария возвращается явная ошибка. Служебное завершение процессов может занять небольшое время сверх дедлайна. Обычный результат имеет reproducible=true и побитово повторяется на фиксированных версиях зависимостей при том же seed/лимитах, включая разное число процессов. Аварийный частичный результат имеет stop_reason=time_budget, reproducible=false и явное сообщение в интерфейсе: невозможно одновременно обещать произвольный жёсткий wall-clock предел и одинаковый объём работы на машинах любой скорости. Это ограничение не скрывается за статусом воспроизводимого результата.

Подбор по h: n от max(1,N_formula−2) до N_formula+6; по n: h по решётке min→max. Остальные ветки и периоды неизменны. Каждый кандидат проверяется по seeds_final. Условия: не тупик, есть выпуски, средняя задержка ≤0.1h и локальный D≤service_targets.max_denied_share. Общий парк ограничивает диапазон, поезда не берутся из чужого депо молча. Нет подходящего — not_found_in_range, а не подставленное значение. Результат содержит формулу, найденную симуляцию и измеренные факторы: сумма (n_on+n_off)/boarding_rate, случайных задержек и ожиданий ресурсов за выбранный период, в поезд-с. Отдельно показано ожидание у общих станций/участков; это наблюдаемое место блокировки, а не доказательство причинности другой ветки. Задержка выпуска и доля отказов сравниваются с конкретными порогами. При неуспехе приведена диагностика последнего проверенного кандидата, при пустом диапазоне — ограничение доступного парка.

## Границы применения

Нет динамического переназначения маршрута, ограничений вместимости платформ, лифтов, эскалаторов, однопутных участков, разных типов поездов, серьёзных инцидентов или влияния времени суток на p₀. Данные модельного направления не заменяют реальную OD. Лондон использует входы NUMBAT 2025 TWT и топологию TfL API после повторной успешной загрузки. Исходный интервал h = round(3600 / среднее число поездов за час по выбранным перегонам и обоим направлениям ветки); это `estimate`, поскольку один симметричный интервал модели не воспроизводит разные частоты. Длины — расстояния большого круга по координатам (`estimate`), без выдуманных фактических времён хода. Входы LU-станций относятся ко всем их линиям, а модель назначений ограничена участком; доли входа для выбранных линий не выдумываются. Статус каждого параметра и ограничения описаны в london_data_audit.md. Численный разрыв скорости средней сети описан с замерами в performance.md.
