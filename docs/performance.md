# Производительность

Измерено 22.11.2026, Windows 11, CPython 3.13.14, один процесс. Команда: `.venv/Scripts/python -m scripts.benchmark`. Полные сутки 05:00–25:00, seed 42, спрос Пуассона. Измеряется конструктор симулятора + весь run; без сокращения времени/пассажиров.

| Сеть | Станций | Пассажиров | Симуляция, с | Сериализация траектории, с | JSON, MB |
|---|---:|---:|---:|---:|---:|
| Простая | 6 | 27 263 | 0.478 | 0.038 | 2.52 |
| Средняя | 25 | 117 866 | 4.730 | 0.190 | 11.01 |
| Звезда | 13 | 59 930 | 1.512 | 0.096 | 6.06 |

Исходная средняя сеть: 7.570 с. После профилирования посадка векторизована, группы на борту агрегируются, нулевые переходы не создают heapq-события: около 48 тыс. событий вместо 335 тыс. Все проверки сохранения/траектории проходят.

**Разрыв:** средняя сеть превышает целевые 3 с на 1.73 с. Скрытого уменьшения сети/суток нет. Следующее конкретное улучшение — компактные массивы FIFO с пакетной генерацией/пересадками либо numba для ядра посадки (Python остаётся языком проекта). Получение траектории будет отдельно измерено через HTTP после API. Поиск использует только метрики, без записи траектории; независимые оценки будут распараллелены в спринте 5.

Оптимизация средней сети, те же полные сутки, настройки по умолчанию (3 seed поиска / 5 итоговых), 16 процессов: **45.977 с**, 61 оценка seed/сценарий, 1 поколение, 8 точек итогового фронта, 4 карточки. Бюджет 60 с выполнен в этом замере. Первая реализация проверяла бюджет только после всей начальной популяции и заняла 97.405 с; исправлена пакетная проверка времени. Число поколений ограничивается временем; 30 — верхняя граница. Машинный итог: optimizer_benchmark.json.
