# Аудит Лондона: повторная загрузка 22.11.2026

TfL снова доступен: страницы Open Data, API Jubilee/Bakerloo и официальный каталог NUMBAT вернули HTTP 200. Регистрация для использованных публичных файлов не потребовалась. Синтетический спрос в `datasets/london/london_subset.json` заменён опубликованными входами станций. `meta.synthetic=false` означает реальное происхождение входных потоков и топологии, а не отсутствие модельных допущений.

## Источники и период

- [TfL Open Data](https://tfl.gov.uk/info-for/open-data-users/our-open-data) объясняет NUMBAT как типичный день осени, обработанный по нескольким источникам с исключением аномальных событий.
- [Каталог NUMBAT](https://crowding.data.tfl.gov.uk/#!NUMBAT%2FNUMBAT%202025%2F) содержит файлы MON, TWT, FRI, SAT, SUN за 2025 год.
- Использован [NBT25TWT_Outputs.xlsx](https://crowding.data.tfl.gov.uk/NUMBAT/NUMBAT%202025/NBT25TWT_Outputs.xlsx), **типичный вторник–четверг осени 2025**. Это не конкретная календарная дата. Дата на обложке файла: 01.07.2026. SHA-256: `a10e5f767750538ecac99cf0d2131243672574df88b9c933f03b9357c5f67db2`.
- Топология и геокоординаты: [Jubilee outbound](https://api.tfl.gov.uk/Line/jubilee/Route/Sequence/outbound) и [Bakerloo outbound](https://api.tfl.gov.uk/Line/bakerloo/Route/Sequence/outbound), снимок от 22.11.2026. 2025 потоки объединены с текущей топологией 2026 — это явное ограничение временного соответствия, не исторический снимок всей системы.

Сохранены `datasets/london/sources/jubilee_route.json`, `bakerloo_route.json`, `numbat_2025_twt.json` и `import_audit.json`. Excel не изменялся. Вместо большого бинарного файла в Git находятся точные нужные строки с номерами, значениями всех 96 четвертей суток и метаданными исходного файла; его можно заново скачать по ссылке и проверить hash.

## Контроль импорта

14 станций Jubilee Green Park → North Greenwich и Bakerloo Piccadilly Circus → Elephant & Castle. Общий Waterloo. Наименования NUMBAT сопоставлены явно: Waterloo LU, London Bridge LU, Canary Wharf LU, Charing Cross LU, Elephant & Castle LU. Строки Canary Wharf DLR/EL не суммируются с LU.

В файле время 05:00–следующие 05:00. Номер четверти q=21 соответствует 05:00, q=97 — 24:00: `start_min=(q−1)·15`. Импортируется диапазон 300≤start_min<1500 (ровно 80 четвертей), остальная часть суток сохраняется в выдержке источника и не добавляется в симуляцию. По каждой станции сумма всех 96 исходных значений сверена с колонкой Total. Дополнительно независимым чтением openpyxl проверены все 96 значений каждой из 40 отобранных строк (14 входов + 26 частот): они совпадают с выдержкой побитово как Python float. За выбранные 20 часов сумма входов **573 558.453090302**. Дробность присутствует уже в опубликованных данных NUMBAT; округления до целых при импорте нет. Seed-прогон при включённом Пуассоне имеет другое фактическое число появившихся пассажиров.

Пропущенная станция, пустая/некорректная числовая ячейка, несовпадение суммы Total, нарушение последовательности четвертей или нулевая частота целого часа прерывают импорт. Пустая ячейка не заменяется нулём, нулевая частота не заменяется 180 секундами. Частоты двух направлений/перегонов отличаются, поэтому усреднённый интервал — оценка. Первый час Bakerloo даёт 1800 с, что допустимо для исходного пользовательского расписания, но выше границы поиска оптимизатора 1200 с; «Мой вариант» сохраняет его, поисковые варианты подчиняются решётке оптимизатора.

## Ограничения интерпретации

Station_Entries — входы на LU-станцию всех её линий. Выбранный участок не включает все эти линии и внешние назначения. Значения не уменьшались выдуманной долей Jubilee/Bakerloo: весь реальный вход используется, а модель выбирает назначения только внутри участка. Поэтому результат не является валидированным прогнозом реальной нагрузки Лондона, хотя входы взяты из данных. В частности, Waterloo включает вход с других линий; пересадки на отсутствующие линии и пассажиры, приходящие поездом извне участка, не воспроизводятся.

Перепроверка дверей завершена 22.11.2026. Все четыре источника доступны HTTP 200; точные короткие выдержки, URL и SHA-256 извлечённого текста сохранены в `sources/platform_doors_audit.json`:

- [TfL FOI-0284-2627](https://tfl.gov.uk/corporate/transparency/freedom-of-information/foi-request-detail?referenceId=FOI-0284-2627), 19.05.2026, объясняет установку дверей на глубоких подземных станциях продления и отсутствие на поверхностных из-за отсутствия моделируемых порывов воздуха. В ответе есть фраза «16 stations», несовместимая с 11 станциями продления; это число **не используется** как число оборудованных станций. Восемь станций имеют шестнадцать направленных платформ.
- [UrbanRail London](https://www.urbanrail.net/eu/uk/lon/london.htm) независимо подтверждает двери на подземных станциях продления 1999 года. Сопоставление этого правила с сохранённой последовательностью TfL даёт ручной список: **Westminster, Waterloo, Southwark, London Bridge, Bermondsey, Canada Water, Canary Wharf, North Greenwich**. Green Park относится к прежнему участку; поверхностные Canning Town, West Ham и Stratford исключены. Список не выдаётся за автоматически импортированный атрибут.
- [TfL FOI-0943-2122](https://tfl.gov.uk/corporate/transparency/freedom-of-information/foi-request-detail?referenceId=FOI-0943-2122), 23.08.2021: дверей на Bakerloo не планировалось; соответствующее объявление Waterloo было ошибкой. Поэтому станционный флаг Waterloo, влияющий также на Bakerloo в формате 1.0, остаётся **явным модельным приближением**, а не физическим фактом.
- [Crossrail: Engineering Design of Platform Edge Screens](https://learninglegacy.crossrail.co.uk/documents/engineering-design-platform-edge-screens-crossrails-mined-stations/), 09.07.2018, подтверждает двери всех подземных станций и прямо перечисляет пять mined stations: Bond Street, Tottenham Court Road, Farringdon, Liverpool Street, Whitechapel. Справочная инвентаризация подземного участка Elizabeth также включает box stations Paddington, Canary Wharf, Woolwich: восемь станций / шестнадцать платформ. Поверхностные Custom House и Abbey Wood в этот список не входят. Elizabeth не добавляется в демо.

Это перепроверенная **ручная** разметка (`source=user`); отсутствие признака в API и неоднозначное число в FOI не скрываются. Код импорта читает этот сохранённый список, а тест проверяет его точное соответствие флагам сети. Суммы аудита вычисляются через `math.fsum`, чтобы точная offline-пересборка совпадала и на Python 3.11, и на 3.12/3.13. Сырые значения NUMBAT сохранены без округления.

В интерфейсе сеть называется «Лондон / TfL NUMBAT 2025 TWT», имеет пометку данных, источники чисел и раскрываемый блок с границами модели. Старый fallback-генератор сохраняет результат только в `.verification/`, чтобы случайный запуск не перезаписал реальный набор.

## Воспроизведение

Из корня: `.venv/Scripts/python -m data_io.tfl.import_london` — пересобрать сеть и аудит из сохранённых источников без интернета. Добавьте `--refresh` для повторного скачивания опубликованного Excel и обоих API. `httpx` для refresh установлен штатным setup.py; Excel читается стандартной библиотекой, новых зависимостей нет. Тесты не используют сеть.

Первоначальные HTTP 403 сохранены в `docs/london_research.json` как историческое свидетельство. Они больше не описывают текущую доступность TfL. История первого synthetic fallback остаётся в `progress.md`; действующие источники описаны здесь.
