# Решения

1. Репозиторий уже создан; корень checkout соответствует `metro-sim/` из ТЗ. Python 3.13 для локальной среды, поддержка 3.11+. Canvas для карты, SVG для Парето: без дополнительных UI/графических библиотек.
2. Исполнение последовательно, спринты 0–9. Значения из JSON с `{value, source}` нормализуются для вычислений отдельно от исходного документа; происхождение сохраняется в отчёте.
3. Платформа направления относится к физическому коридору. Ветки с общим перегоном используют одну пару платформ на общей станции; пересекающиеся только в пересадочном узле ветки имеют отдельные платформы. Иначе крестовая пересадка неправдоподобно блокирует перпендикулярные поезда. Направления общего коридора согласуются по порядку общих рёбер, а не id ветки.
4. Раздел 5 допускает пропуски спроса с нулём пассажиров; проверка покрытия выдаёт предупреждение. Терминальная стоянка включает base/двери/высадку перед освобождением платформы: это согласуется с формулой 6.5 и правилом задержек на конечной.
5. Траектория дополнена агрегированными `queue_events` (time, station, delta). Срезы series каждые 60 с сами по себе не позволяют точно восстановить очередь в произвольное время; дельты решают эту неоднозначность без запросов к серверу. Нулевые переходы обрабатываются атомарно в событии высадки.
6. Для локального расчёта поездов `denied_share` по ветке/периоду = повторные отказы / севшие на этой ветке за период. Это интенсивность отказов на обслуженного пассажира поездки, а не вероятность, ограниченная единицей. При положительных отказах и нулевой посадке значение очень большое. Глобальная D строго по всем появившимся пассажирам.
