# Решения

1. Репозиторий уже создан; корень checkout соответствует `metro-sim/` из ТЗ. Python 3.13 для локальной среды, поддержка 3.11+. Canvas для карты, SVG для Парето: без дополнительных UI/графических библиотек.
2. Исполнение последовательно, спринты 0–9. Значения из JSON с `{value, source}` нормализуются для вычислений отдельно от исходного документа; происхождение сохраняется в отчёте.
3. Платформа направления относится к физическому коридору. Ветки с общим перегоном используют одну пару платформ на общей станции; пересекающиеся только в пересадочном узле ветки имеют отдельные платформы. Иначе крестовая пересадка неправдоподобно блокирует перпендикулярные поезда. Направления общего коридора согласуются по порядку общих рёбер, а не id ветки.
4. Раздел 5 допускает пропуски спроса с нулём пассажиров; проверка покрытия выдаёт предупреждение. Терминальная стоянка включает base/двери/высадку перед освобождением платформы: это согласуется с формулой 6.5 и правилом задержек на конечной.
5. Траектория дополнена агрегированными `queue_events` (time, station, delta). Срезы series каждые 60 с сами по себе не позволяют точно восстановить очередь в произвольное время; дельты решают эту неоднозначность без запросов к серверу. Нулевые переходы обрабатываются атомарно в событии высадки.
6. Для локального расчёта поездов `denied_share` по ветке/периоду = повторные отказы / севшие на этой ветке за период. Это интенсивность отказов на обслуженного пассажира поездки, а не вероятность, ограниченная единицей. При положительных отказах и нулевой посадке значение очень большое. Глобальная D строго по всем появившимся пассажирам.
7. Вместо зависящего от скорости отсечения нормальный поиск ограничен evaluation_budget (default 20) и generations. Начальная популяция при малом лимите занимает не более половины оценок (минимум 4), чтобы оставить место потомкам. Ранжирование использует seeds_search, но для каждого кандидата заранее заканчиваются также seeds_final: на дедлайне нет дополнительной долгой финальной фазы. При одинаковом seed и завершённом лимите результат побитово повторяется, включая разные числа процессов. Аварийный time_budget_s прерывает незавершённые прогоны и процессы; возвращаются только полностью оценённые кандидаты с reproducible=false и явным сообщением. Если не завершён даже исходный сценарий, выдаётся ошибка. Одновременно гарантировать одинаковый объём вычислений и произвольный wall-clock предел на любой машине невозможно; обычный воспроизводимый поиск и аварийный частичный результат теперь явно различаются. Предыдущая схема 35%/55% и мягкая финальная фаза отменены.
8. POST /validate возвращает 200 с диагностическим отчётом даже для невалидной сети: этот endpoint показывает ошибки в конструкторе. Simulate/optimize/train-count с такой сетью возвращают 422 с тем же отчётом. Ошибка структуры HTTP-запроса тоже 422. Отмена завершённой задачи сохраняет terminal status; отмена queued/running немедленно видна, рабочие процессы прекращаются при ближайшей проверке (50 мс), а не дожидаются конца суточного прогона.
9. TfL (страницы, Unified API) и справочная страница о дверях недоступны HTTP 403. Спринт 8 использует явно разрешённый synthetic fallback: Jubilee Green Park—North Greenwich + Bakerloo Piccadilly Circus—Elephant & Castle, общий Waterloo. Спрос полностью модельный, параметры assumption; координаты — ручная схема. Проверку спорного списка дверей выполнить не удалось, статус предварительный. Из-за станционного (не платформенного) флага Waterloo получает одинаковую добавку стоянки для обеих веток; это ограничение формата ТЗ явно описано в аудите.
10. Повторная проверка 22.11.2026: TfL и NUMBAT доступны HTTP 200, решение 9 о synthetic fallback больше не описывает активную сеть. Импортированы NUMBAT 2025 TWT и снимки API 2026; типичный день не называется конкретной датой. `synthetic=false` относится к реальному происхождению входов и топологии; OD, парк, физика и прочие допущения явно отделены. Полные входы LU-станций не масштабируются выдуманной долей выбранных линий; модель ограничена назначениями внутри участка, что прямо указано в интерфейсе и аудите. Интервалы — оценка из среднего числа поездов обоих направлений/перегонов за час, длины — оценка большого круга. Сохранённые строки с номерами и hash Excel позволяют пересборку без сети; изменение структуры/пропущенные значения блокируют импорт. Генератор старого fallback пишет только в игнорируемую .verification и не перезаписывает real-data demo. Дальнейшая независимая проверка дверей выполнена (пункт 11); источник ручной разметки остаётся user, а не data.

11. Двери перепроверены по доступным TfL FOI-0284-2627, FOI-0943-2122, UrbanRail и инженерному материалу Crossrail. Ссылки, HTTP 200, точные выдержки и SHA-256 текстов сохранены в datasets/london/sources/platform_doors_audit.json. Ручной список Jubilee: Westminster, Waterloo, Southwark, London Bridge, Bermondsey, Canada Water, Canary Wharf, North Greenwich. Поверхностные Canning Town, West Ham, Stratford исключены. Фраза TfL о «16 станциях» противоречит 11 станциям продления и не принимается как число станций: 8 оборудованных станций имеют 16 направленных платформ. Waterloo остаётся свойством станции формата 1.0 и добавляет время также Bakerloo; FOI явно подтверждает, что это модельное приближение.
12. При посадке проверяется вся упорядоченная поездка в направлении поезда, включая циклический порядок кольца. Таблица допустимых поездок по ветке/направлению кэшируется. Массовая генерация записывает NumPy-группы пакетами; FIFO-время и дробный размер сохраняются. Индекс объединения нужен только в текущий момент события и очищается при смене времени, а не по одной записи на каждую посадку. Регрессия сравнивает пакетную генерацию со скалярной на сетях с обоими видами пересадок и проверяет сохранение каждого события.
13. Панель очереди и карта используют один модуль replay.ts с точными queue_events; минутные series не заменяют выбранный момент. При усреднении метрик строки объединяются по id ветки/направлению/периоду; отсутствующие проходы дают нулевой вклад в тепло, отсутствующий интервал остаётся null. Локальные причины расхождения формулы/симуляции измеряются в поезд-с, а не выдаются общим перечнем возможных причин.
14. Для агрегатов аудита TfL применяется math.fsum. В Python 3.12 изменился алгоритм builtin sum, что ранее давало несовпадение последних разрядов offline-аудита с Python 3.11. Сырые 15-минутные значения не округляются и не меняются; точное сравнение пересобранной сети/аудита сохранено.
