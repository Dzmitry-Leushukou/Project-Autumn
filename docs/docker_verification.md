# Docker Compose: запуск и проверка

22.11.2026. Конфигурация: `compose.yaml`, `docker/api.Dockerfile`,
`docker/web.Dockerfile`, `docker/nginx.conf`, `.dockerignore`.

Команда из корня: `docker compose up --build -d --wait`.
Интерфейс: http://localhost:8080, Swagger: http://localhost:8080/api/docs.
Подробная инструкция, остановка, логи, смена порта и работа с файлами — в README.

## Устройство

- `api`: Python 3.13 slim, точные зависимости из requirements.lock.txt, исходники
  и готовые datasets. Выполняется пользователем uid 10001, без root. Один процесс
  Uvicorn владеет памятью задач/прогонов; оптимизатор создаёт свой multiprocessing pool.
- `web`: frontend собирается в Node 24 Alpine через npm ci / npm run build;
  конечный образ — Nginx 1.28 Alpine со статическими файлами. Node/Vite при работе не нужны.
- `/api/` проксируется во внутренний API. `--root-path /api` сохраняет правильные
  адреса OpenAPI и Swagger за прокси. Ссылка API в frontend задаётся при Docker-сборке
  через VITE_API_DOCS_URL; обычный запуск без Docker сохраняет прежний адрес.
- Опубликован только `127.0.0.1:8080`, меняется через METRO_PORT. API не публикуется
  отдельным портом хоста. DNS upstream обновляется при пересоздании API-контейнера.
- Healthcheck API проверяет /health, healthcheck web — /api/health через Nginx.
  Compose ждёт API перед запуском frontend и готовность обоих при --wait.
- Модели и пользовательские изменения не монтируются с хоста автоматически.
  Для изменения кода/datasets требуется пересборка. Загрузка/сохранение JSON
  через браузер работает как прежде. Постоянных volumes и базы данных нет.
- `.dockerignore` исключает .git, локальные зависимости, кэши, .env, журналы,
  временные проверки и отчёты из контекста сборки.

## Выполненные проверки

Среда: Docker Desktop 4.65.0, Docker Engine 29.2.1, Compose 5.1.0,
Linux-контейнеры на Windows. Python в собранном образе — 3.13.18.

| Проверка | Результат |
|---|---|
| docker compose config --quiet | Успешно |
| docker compose build | Оба образа собраны, включая TypeScript/Vite |
| docker compose up -d --wait | Оба сервиса healthy |
| nginx -t | Конфигурация корректна |
| UI, /api/health, /api/docs, /api/openapi.json, /api/networks | HTTP 200, семь демо, OpenAPI server=/api |
| POST /api/simulate + GET trajectory | Рассчитана сеть, траектория непустая |
| Train-count по интервалу и по парку | Оба режима found, есть диагностика |
| Отмена оптимизации | Статус cancelled |
| Невалидная сеть / отсутствующая задача | HTTP 422 / 404 |
| Chromium через Nginx, METRO_E2E_BASE_URL=http://127.0.0.1:8080 | **6 passed**, 36.5 с |
| Ссылка Swagger/OpenAPI без Docker, свежие dev-серверы | **1 passed**, 16.7 с |
| Локальный production build | Успешно |
| Локальный pytest, последовательный повтор | **69 passed**, 12.57 с |
| pytest в собранном API-образе, tests/scripts смонтированы только для проверки | **69 passed**, 13.94 с |
| docker compose stop + start --wait | Оба сервиса снова healthy |
| METRO_PORT=8081 + up -d --wait | UI-прокси на новом порту, health OK; затем возвращён 8080 |

Шесть браузерных сценариев проверяют API-документацию, демо с оптимизацией и
сравнением, среднюю сеть/анимацию/мобильную ширину, конструктор, Лондон и
точную очередь с перемоткой. Docker-образ проверялся через настоящий Nginx,
Vite и локальный Python backend для этих шести сценариев не запускались.
Тестовые скриншоты/замер анимации восстановлены после прогона, чтобы не заменять
исторические артефакты случайными кадрами нового запуска.

Первый Python-прогон параллельно с другими проверками дал 67 passed и два
превышения порога 2 с при запуске/остановке multiprocessing pool. Отдельный
повтор этих двух тестов на исходной чистой копии и последовательный полный
прогон рабочей папки проходят. Порог и код ядра не менялись; результаты замеров
времени зависят от нагрузки машины. Предупреждение Starlette TestClient о
BlockingPortal остаётся сторонним DeprecationWarning.

В GitHub Actions добавлен отдельный job `compose`: сборка и запуск контейнеров,
шесть браузерных сценариев через Nginx, вывод логов, остановка и сохранение
скриншотов. Новый удалённый CI в рамках этой проверки не запускался.
